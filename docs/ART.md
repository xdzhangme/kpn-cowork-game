# Pixel art system

All art is original and procedural. No external artwork is used.

## Layout

- `src/art/palette.js` maps one-letter palette indices (`o` outline, `w` wall, `f` floor, `a` accent, ...) to theme tokens. Colors come from CSS variables set from `public/theme.json`, so changing the theme recolors every sprite. Extra tokens (wood, leaf, skin, room tints) fall back to defaults.
- `src/art/sprites.js` defines every sprite as an array of strings using those indices (`.` is transparent). It contains tiles, about 40 props, 12 `reward-*` icons, the interaction `bubble`, and the character.
- `src/art/atlas.js` renders sprites to cached canvases, recolors them from the live palette (cache is invalidated when theme styles change), and draws tiles, props and the character.

## Character

16x24 px, 4 directions (`down`, `up`, `left`, `right`) x frames 0-3. Frame 0 is idle, 1 and 2 are strides, 3 is the passing pose. The walk cycle is `[1, 3, 2, 3]`.

## Map

`src/data/office-map.json` is generated by `npm run build:map` (`scripts/build-map.mjs`). It has a 40x61 tile grid and 15 rooms: reception, the Chat vs Cowork intro room and the lounge along the entrance corridor at the top; a central spine with three branch corridors; 8 department rooms interleaved with the general meeting room, print room, open workspace and cafeteria on both wings, in different sizes and with doors on whichever wall faces a corridor. The `PLAN` array holds each room's interior rect, door side and furniture set; corridors, walls and the outer building outline are derived from it. 51 object slots (`slots`) are bound to the 50 KPN use cases plus the intro explainer (`objects`). Props use footprints in tiles; sprites are bottom-aligned to the footprint. Edit the generator, not the JSON.

## Engine changes

Placeholders were replaced via the atlas. The only behavior change is the walk cycle in `src/player.js`.

## Room identity

Each room has its own floor pattern (loor in ooms[]: grid, checker, dots, tiles8, stripes, bands, planks, hatch, diamond, zigzag), a wall sign plaque with a room icon (sign-<room id> sprites), a distinct furniture set and desk layout (see LAYOUTS and DECOR in scripts/build-map.mjs). Patterns use the room tint plus two shades mixed from the theme outline color, so they recolor with the theme.

## Reachability check

`npm run check:map` flood-fills the player's real collision box (`blocked()` from `src/player.js`) from the spawn point and fails if any room cannot be entered or any slot has no reachable tile within interaction range. Run it after every `npm run build:map`. (It caught the open workspace being sealed off from the corridor.)

The check also fails when two props overlap or a prop sits on a doorway. Room decoration (`extra` lists in `scripts/build-map.mjs`) is placed greedily: a candidate that overlaps another prop or crowds the two-tile apron in front of a door is skipped. Themed props (scales, trophies, ledgers, servers, pallets, easels, coat racks, microwaves, cacti) all use palette indices, so they recolour through `theme.json`.
